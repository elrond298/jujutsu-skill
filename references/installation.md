# Installing and setting up Jujutsu

A useful setup has four parts: a current `jj` binary, Git 2.41 or newer, author identity, and one repository where you can verify the working-copy model.

## Install a released binary

Prebuilt binaries for Windows, macOS, and Linux are available from the [latest release](https://github.com/jj-vcs/jj/releases/latest). The Linux musl build is the most portable download.

Common package-manager choices:

```bash
# Homebrew on macOS or Linux
brew install jj

# Arch Linux
pacman -S jujutsu

# openSUSE Tumbleweed
zypper install jujutsu

# FreeBSD
pkg install jujutsu
```

```powershell
# Windows
winget install jj-vcs.jj
# or
scoop install main/jj
```

With `cargo-binstall`:

```bash
cargo binstall --strategies crate-meta-data jj-cli
```

Build from source only when a package or release binary does not meet the need. It requires Rust 1.88 or newer and native build tools:

```bash
cargo install --locked --bin jj jj-cli
```

Use the Git URL form from the official installation page only when you deliberately want a prerelease build.

## Verify runtime requirements

```bash
jj --version
git --version
```

Jujutsu requires Git 2.41 or newer at runtime. Older distributions such as Debian 11 and Ubuntu 22.04 may need a newer Git package.

## Set author identity

```bash
jj config set --user user.name "Your Name"
jj config set --user user.email "you@example.com"
jj config get user.name
jj config get user.email
```

Repository-specific settings use `--repo` instead of `--user`.

## Create a first repository

Clone a Git repository:

```bash
jj git clone URL [DESTINATION]
```

Or add Jujutsu to the current directory:

```bash
jj git init
```

Current versions colocate by default, leaving both `.jj/` and `.git/`. Pass `--no-colocate` only when ordinary Git tools do not need the working directory. Read [colocated-repos.md](colocated-repos.md) before choosing.

Verify the model with a small exercise:

```bash
jj st
jj desc -m "Describe first change"
# edit a file
jj --no-pager diff --git
jj new
jj --no-pager log
```

The exercise should show that the working copy is a commit, file edits need no staging command, and `jj new` starts the next change.

## Enable completion

Dynamic completion includes bookmarks, revisions, operations, files, and context-sensitive flags. It is the preferred option, with standard completion as a fallback.

```bash
# Bash
source <(COMPLETE=bash jj)

# Zsh, after compinit
source <(COMPLETE=zsh jj)

# Fish 4.0.2 and newer loads dynamic completion automatically
```

```powershell
$env:COMPLETE = "powershell"
jj | Out-String | Invoke-Expression
Remove-Item Env:\COMPLETE
```

PowerShell profile scripts require an execution policy of at least `RemoteSigned`. Nushell currently uses the standard script generated by `jj util completion nushell`.
